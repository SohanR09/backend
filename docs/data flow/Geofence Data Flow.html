One position update, end to end

  1. The vehicle sends vehicle_id, latitude, longitude and an ISO 8601 timestamp. This route is rate limited per client.
  2. The handler validates the body, then loads the vehicle. Unknown vehicles get a 404.
  3. The store returns every geofence whose polygon contains the point, boundary included.
  4. The location is saved. If it is the newest one for that vehicle, the stored set of geofences it is inside is replaced in the same step, and the previous set is returned.
  5. Each difference between the previous and new set becomes a row in violations. Newest locations only.
  6. For each entry or exit, the store checks for an active alert rule for that vehicle and geofence. Several matching rules still give one alert.
  7. A matching event goes onto an in-memory queue without blocking. Only when a rule matched.
  8. The response lists the geofences the vehicle is now inside, plus time_ns. An out-of-order older report is stored but leaves the state unchanged.
  9. The worker saves the event in alert_events, which is what GET /alerts/events reads later.
  10. The event is encoded as JSON and handed to the hub.
  11. The hub writes it to every connected WebSocket client, so the dashboard updates without polling.

What every request passes through

  1. recovererA panic becomes a JSON 500 instead of a dropped connection.
  2. corsAdds the allowed origin so the browser frontend can call the API.
  3. loggerLogs method, path and status.
  4. authNeeds an API key when one is set. /health is exempt. The WebSocket may pass it as ?api_key=.
  5. limitBodyCaps request bodies at 1 MiB (413 above that).
  6. routerMatches method and path, then wraps the result with time_ns.
  7. rateLimitOnly on POST /vehicles/location. Over the limit gets a 429 with Retry-After.
