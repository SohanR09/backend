Fenceline: End-to-End Data Flow

Geofencing and real-time vehicle alerts. React 19 + Redux Toolkit + Leaflet frontend, Go 1.24 API, PostgreSQL 16, own WebSocket hub.

30-second pitch: A vehicle position is posted to the API. The server finds which zones contain it (GiST bounding-box index, then exact ray casting), compares that set with the vehicle's previous set to detect entry and exit, writes every transition to history, and, only if an alert rule matches, hands the alert to a background worker that stores it and pushes it over WebSocket to every open dashboard. The HTTP response never waits for the push.

2. Core flow: a vehicle position becomes an alert

Triggered from the Live page: pick a vehicle, click the map. onPick dispatches the sendLocation thunk.

  1. Browser sends the position syncapi.sendLocation posts {vehicle_id, latitude, longitude, timestamp}; the timestamp is the browser's new Date().toISOString(). The X-API-Key header is added only if configured.
  2. Middleware syncOrder: recoverer, cors, logger, auth, limitBody, mux. Auth uses constant-time compare. The per-IP token bucket (50/s, burst 100) wraps only this route; excess gets 429 + Retry-After. handle() then times the handler and adds time_ns.
  3. Validate, load vehicle syncFinite numbers, lat in [-90,90], lon in [-180,180], RFC 3339 timestamp, vehicle must exist (404 otherwise).
  4. Which zones contain the point? (two-phase) syncPhase 1: bbox @> degenerate box(point) uses the GiST index, so only a few candidate polygons come back. Phase 2: exact even-odd ray casting in Go; a point on an edge or vertex counts as inside.
  5. Atomic state change per vehicle syncOne transaction: SELECT ... FOR UPDATE on the vehicle row (serialises concurrent updates for that vehicle), compute max(recorded_at) to decide isLatest, insert into vehicle_locations, read the previous zone set, and only if latest replace vehicle_geofence_state. An older, out-of-order report is stored but changes no state and fires no events.
  6. Transition detection syncSet difference: in now but not before = entry; in before but not now = exit. The first ever report inside a zone counts as an entry.
  7. History always, alert only if a rule matches syncEvery transition is written to violations. HasActiveAlertRule checks rules where the vehicle is NULL (all) or equal, and the event type is both or equal. Several matching rules still produce one alert.
  8. Hand off, do not wait asyncenqueue pushes to a buffered channel (1024). If it is full, a goroutine retries for 5 s, then logs a drop. The HTTP response is returned immediately with the current zones.
  9. Worker persists then broadcasts asyncdeliver inserts into alert_events (JSONB), then Hub.Broadcast puts the payload into each client's 64-slot channel. A client whose buffer is full is dropped, so one slow tab cannot stall the rest.
  10. Browser reacts asyncsocket.onmessage checks the shape with isAlert, then dispatches alertReceived (de-duplicated by event_id, feed capped at 100), pulseVehicle (marker flashes), and fetchLocations (marker moves, inside/outside colour updates).

4. Frontend strategies (what is implemented)

Single source of truth. Five Redux slices. Components never call fetch; only thunks call api.ts, which is the one place that sets headers, parses errors and converts network failure into a readable ApiError.
Refetch after write, not optimistic updates. After POST/DELETE the thunk reloads the list, so the UI always shows what the server actually stored (including server-generated ids).
Two ways to stay fresh. WebSocket for instant alerts, plus a 10 s poll of positions as a safety net. The socket handler also refreshes positions because an alert means a vehicle moved.
Resilient socket. Opened once in main.tsx, outside React, so StrictMode cannot open it twice. Exponential backoff 1, 2, 4 ... capped at 15 s. On every (re)connect it calls fetchEvents and merges by event_id, filling any gap while offline. The sidebar shows connecting / live / reconnecting / offline.
UI signals through the store. ui.focus and ui.pulse carry a nanoid key, so clicking the same alert twice still re-triggers the map animation. Status per slice: idle, loading (first load only), ready, error, with a retry button.
Runtime config. public/config.js sets window.__CONFIG__ before the bundle runs, so the API address can change on a deployed build without rebuilding; VITE_* is the fallback. SPA rewrites (vercel.json, _redirects) make refresh on /zones work.

6. Honest limits (say these before they ask)

Single instance only for live push. The hub is in memory, so with two API instances an alert reaches only clients on the instance that handled the update. Fix: Postgres LISTEN/NOTIFY or Redis pub/sub.
Alerts are at-most-once. The violation row is committed before the queue, so history is the source of truth; but an alert still in the in-memory queue during a crash is lost. Reconnect catch-up only returns alerts that were persisted.
Read-path shortcuts. /vehicles/locations runs two queries per vehicle (N+1), and list endpoints load all rows then slice in memory. Fine at demo scale; next step is a single join (DISTINCT ON) and SQL LIMIT/OFFSET.
Security scope. One shared API key, and it sits in the public config.js; WebSocket accepts any origin; the client supplies the timestamp. A real deployment needs per-user auth and a server-side timestamp or skew check.
Geometry. Polygons are planar in lat/lon: right for city-scale zones, not for the antimeridian or poles. Zones cannot be edited or deleted yet.
